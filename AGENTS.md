# AGENTS.md

## What this is

OpenRP is a native desktop roleplay AI engine, built on the [SereChat](https://serechat.com) API. Today it has sign-in, Worlds, Characters and Personas pages (an index filtered as you type, by tag chips and by favourites, which are starred on a card and listed first; plus a form with name, tags, a private comment (`comment`: on cards and in pickers, never in a prompt or an exported card), description and portrait, sections that open on click (a character's greetings and example dialogue, and lore: `LoreEntry` keys and text, or Always, importable from a SillyTavern lorebook), and a ⋯ menu with Duplicate, Export card and Delete; a saved world's form lists its stories, which open on click; a character's Play asks which world to meet them in; personas are who the user plays: the player form offers them as chips, fills in the starred one and saves what is typed as one, `Player.portrait` showing in the You chip), character cards (`serechat/src/card.rs`: Import reads PNG or JSON V1/V2/V3 cards, the PNG becoming the portrait; Export card writes a PNG with both the V2 `chara` and V3 `ccv3` chunks, or JSON without a portrait; `{{user}}`/`{{char}}` are filled in at send time by `serechat::macros`), stories (Play on a world starts a session, which first asks who the user plays and is saved and listed once they Begin; its cast holds copies of library characters, present or absent in the scene, each with a menu to store it in Characters (updating the character it was cast from), edit (name, description, portrait) or delete it, and Add offers From characters, Create character and Generate character (a separate request whose system prompt only lets the model call `create_character`; the result opens for review); the world, player and whole cast (described, with their example dialogue) and the constant lore make up the system prompt, kept stable so providers cache it; the scene, who is present or elsewhere, the lore whose keys the latest two turns mention (`stream::lore_in_play`), memories and the author's note are the story state, appended to the latest prompt (or the latest call result) at send time and never saved (`stream::story_state`, `attach_state`); a story nobody wrote in yet opens with the greeting of the first present member whose library character has one (`Chat::greet`, a reply whose `speak` call already ran; the other greetings are its `swipes`, swiped with ‹ › until the first prompt; a history opening with it is sent after a user `(The story begins.)`); deleting a world deletes its stories, its Delete row naming how many), no narrator: every reply must call tools (`tool_choice: required`), `speak`: everything characters say and do in a reply as `messages` (character, action, text), one per character (duplicates merge into one bubble and the model is told), shown as they stream as bubbles with the character's portrait; text outside tool calls is dropped (no narration); `speak` takes a required `scene` (the place and ambiance when they change, else empty; kept on the session, sent in the story state, shown above the cast and editable there by clicking it), an optional `leave` list (members who move out of the scene) and a required `introduce` list (newcomers with descriptions, cast before their lines; the prompt allows newcomers only when the user refers to someone not cast yet or no one is in the scene); no one is cast without a description: someone who acts uninvited is reported and the next request forces `create_character` (a repair round); `create_character` adds someone not acting yet or describes an undescribed member (calls in a reply run creations first); `update_character` renames (the old name joins the member's `aliases`, as does a rename by the user) or redescribes a member; every name in a call is matched by `chat/names.rs` (case and punctuation folded, then aliases, then a unique partial name such as "Rex" for "Captain Rex") and the model is told the name to use; a reply that only called tools continues on its own, at most 3 times), memories (`remember` tool appends facts to the session's `memories`, sent in the story state, undone with their reply, edited by hand via the Memory button; every 8 prompts, or on `/memorize`, a separate request with `remember` forced reads the turns since the last review and adds more; `reviewed` counts prompts, and a review that fails or takes over 3 minutes leaves its turns for the next, `stream.rs`), an author's note (session `note`, last in the story state) and `/ooc` instructions (a line starting `/ooc` in a user message; `stream.rs` marks it for the model, shown muted), duplicating and exporting sessions (exact copy with costs zeroed, or a frame: world, player, cast and note only; export as a text transcript or a SillyTavern JSONL chat, `chat/export.rs`; unloaded sessions are read first), Write for me (`/impersonate`, `chat/impersonate.rs`: a `SendJob` with `tool_choice: none` whose text streams into the composer, from the draft there; billed with the next reply), streaming Markdown replies with model and reasoning pickers, a background model setting (memory reviews, summaries and character generation; summaries fall back to the story model when it has the larger context window), retries (honouring `Retry-After`; a story reply written as plain text instead of tool calls is retried once, then shown as an error) and context compaction (a story summary keeps the latest turns word for word after it: the summary's `kept` counts the messages before it that the model still reads, `stream::summary_cut`), searchable menus (`Menu::searchable`: characters to cast, the world for Play, personas, models; typing filters by name, then comment and tags, arrows and Enter pick; `chat/menu.rs`), Spotlight search (Ctrl/Cmd+K; library records also by comment, ranked above description; commands, stories also by their world, worlds, characters, models, messages), and a settings page. Tool calls and results are saved on each reply and sent back with the next request (function_call + function_call_output), with a `change` record (cast members before/after, scene before/after) so a turn (a prompt and its replies; `chat/turns.rs`) can be edited (a field per character bubble; saving rewrites the speech in the reply's `speak` call via `tools::respeak`; replies edited into plain text by earlier versions are read back into bubbles by `tools::parse`), regenerated (last turn; the replies it had become swipes on the prompt, `swipes` + `swipe`, switched with ‹ › on the last turn, redoing their `change` records) or deleted; regenerating, swiping or deleting the last turn undoes its changes unless they were changed again since. Problems out of sight (a failed save, unreadable files, the model list) show as notices (`chat/notice.rs`, `WorkerEvent::Problem`) and go to the log. Characters are a local library to reuse across stories; nothing is uploaded (SereChat stores no characters).

- Providers: SereChat (below), or a custom OpenAI-compatible one (config `provider = "custom"`, `base_url`, `api_key`; login's "Use a custom provider" and the settings' Provider tab, both `provider.rs`), spoken to with Chat Completions by `serechat/src/completions.rs`, which turns the same `ResponseRequest` into `/chat/completions` and its chunks into the same `StreamEvent`s. Both credentials are kept: signing out forgets the one in use and carries on with the other. `WorkerEvent::Models` carries the `connection` it was asked for, so a list from a previous provider is dropped; the provider can't change while a reply streams. Custom providers list no prices, so costs (the chat header, Settings › Usage) are hidden while one is in use.
- API: [Responses API](https://serechat.com/docs/responses) (`POST /v1/responses`, SSE streaming); the server's source is in `../serechat` (`app/inference/api/llms/`). tool calls arrive as `function_call` items; results go back as `function_call_output` items (consecutive calls merge into one assistant turn server-side). A stream ends with `response.completed`, `response.incomplete` (`incomplete_details.reason`, e.g. `max_output_tokens`) or `response.failed` (`error.code`: retry `server_error` and `rate_limit_exceeded`, compact on `context_length_exceeded`). `: ping` comments arrive every 15 s. Usage includes `input_tokens_details.cached_tokens` / `cache_write_tokens`; `/v1/models` reports `context_window` and cache prices; `max_output_tokens` defaults to the model's maximum. Reasoning input items are ignored, and there is no server-side conversation state.
- Auth: [OAuth 2.1](https://serechat.com/docs/authentication) (source: `../serechat/app/site/docs/views/pages/AuthPage.tsx`, server in `../serechat/app/oauth/`), `serechat/src/oauth.rs`: authorization code with PKCE (S256) through a loopback listener at `http://127.0.0.1:{port}/callback` (`SignIn`), the consent page in the system browser; `state` and `iss` are checked; pre-registered public client `openrp` (no `/oauth/register`, no secret, no device grant), scope `chat`, `resource=https://serechat.com/v1`. A signed-in `Client` (`Client::signed_in`) refreshes its one-hour access token under one lock its clones share, a minute early or on a `401` (then retries once); refresh tokens rotate and each is saved, under that lock, to the OS keychain (`platform::keep_secret`: Credential Manager, `security`, `secret-tool`). `invalid_grant` (revoked, or 60 days unused) and `insufficient_scope` count as unauthorized: the app signs out and the next consent asks for the scopes again. Sign-out (`Client::sign_out`) forgets the token, then `POST /oauth/revoke`. A `token` line in old configs is dropped.
- Window: its size and maximized state are saved as `window` in the config when the app closes (`Drop for App`) and restored at start; Windows maximizes only after the first frame, since maximizing shows the window.
- Local data: everything but the SereChat sign-in (in the OS keychain) lives in `~/.openrp/`: `config.toml`, `sessions/<id>.json` + `sessions/.index.json`, `worlds/<id>.json`, `characters/<id>.json`, `personas/<id>.json`, `portraits/`, and the app's `desktop.log`, `desktop-crash.log` and `desktop.lock` (one running copy). A session stores its `world` id, `player` (name, aliases, description, portrait), `scene`, `memories`, `note` and `cast` (copies: id, name, aliases, description, portrait, examples, lore, present); the prompt reads the world (and its lore) from the library at send time, and a greeting comes from the library character a member was cast from. Sessions, worlds and characters carry a format `version`: bump it (and upgrade older files in `Session::upgrade`) when the meaning of a field changes; files from a newer version are never saved over. Unknown config lines are kept and written back. Another app also uses `~/.openrp/`; keep file names distinct from its. See `README.md`.

See `README.md` for features, the crate layout and the architecture.

## Hard requirements from the owner

- **Fully Rust-native, custom UI.** Use `winit` + `wgpu` and draw every pixel ourselves. No Tauri, no web views, and no UI frameworks (egui, iced, etc.).
- **Stunning, yet extremely fast.** Performance comes first. Redraw only when something changes, do minimal work per frame, and keep the single-pipeline, single-draw-call renderer.
- **Cross-platform:** it must work on Windows, macOS and Linux.
- **Dependencies are costly.** Add one only if it is truly required and can't reasonably be written by hand. No `thiserror`: write custom error types by hand (`Display` + `std::error::Error`). No `anyhow`, no async runtimes (`tokio`), no convenience crates. Disable default features where possible. OS features go through the tools the platform ships with (see `platform.rs`) rather than new crates.
- **Always use the latest versions** of the dependencies we do use.
- **Cargo workspace:** `crates/serechat` is the API client with no GUI deps; `crates/desktop` is the app (package and binary `openrp`).
- **Military-grade code quality, properly documented.** Every public item has doc comments, `clippy::pedantic` stays clean (`cargo clippy --workspace --all-targets`), and there are no `unwrap`s on fallible runtime paths. Non-trivial logic gets a small unit test. Parsers must survive hostile input (bounded recursion, no slicing off char boundaries).
- **Secrets:** never log the token. Write config files atomically, with `0600` permissions on Unix.
- **Safety:** links from replies only open `http(s)`/`mailto`.
- **Testing:** the owner tests the GUI themselves. Don't drive the app with computer use; `cargo build`, `clippy` and `test` are enough. CI (`.github/workflows/ci.yml`) runs clippy with `-D warnings` and the tests on Windows, macOS and Linux; a `v*` tag publishes release binaries.

## Conventions

- Deliberate shortcuts are marked `ponytail:` with their limit and upgrade path. Current ones: fallback fonts are read fully into memory; no complex-script shaping (Arabic, Indic) or bidi; grapheme clusters follow a practical subset of UAX #29; the world and character forms show no input-method preedit; the file dialogs run a helper process; lore keys are plain words (no regex or secondary keys) and the lore in the story state is capped in characters; compressed PNG text chunks and CHARX cards are not read; the API key field shows the key as typed; the config file uses a flat, string-only TOML subset; the exe icon (`build.rs`, from `assets/icon/`) is embedded for MSVC only; macOS gets its icon from the `.app` and Linux from `openrp.desktop`, both made by the release job from `packaging/`.
- Every file the app writes (sessions, worlds, characters, config) goes through the `Writer` thread in `app.rs`, in order; reads run on workers. The exceptions: a picked portrait (or an imported PNG card's image) is copied in on the picker's worker under a fresh name nothing else writes; an export (card or story) is written by the worker that asked the user where, to that file only; the SereChat refresh token goes to the OS keychain (not a file) from the thread that got it, under the client's token lock, so rotations land in order and never after sign-out; the startup sweep deletes unreferenced portraits older than a day (nothing else ever deletes one, since stories share them, and it skips itself when any story is unreadable); `log.rs` appends to `desktop.log` on a thread of its own; and the panic hook writes `desktop-crash.log` itself, as the process is about to abort. Never write files from the UI thread.
- Failures the user should know about never go only to stderr (release builds on Windows have no console): log them with `log::error` and show them (a notice via `Chat::notify`, or `WorkerEvent::Problem` from a worker). Startup failures show a native dialog (`platform::alert`).
- Glyphs and image thumbnails live in two 2048² atlases packed by `atlas.rs`, which evicts the least recently drawn shelf when full. Portraits are drawn with `library::portrait` (over `Painter::image`, which decodes on a worker on first use).
- Screens never touch disk or network: they push `Action`s; the app runs them (on worker threads when slow) and reports back via `WorkerEvent`. Never block the UI thread.
- Colours and sizes live in `crates/desktop/src/theme.rs`. Colours come from the active `Palette` (`p.theme`), never hard-coded, so all three schemes (Dark default, One Dark, Light) keep working. The look is Zed-inspired: flat surfaces, hairline borders, 4–6px radii, one accent, no gradients or glows.
- Text never assumes a font covers it: layouts go through `Fonts::resolve`, which falls back to Twemoji and the system's CJK fonts.
